## 1. 目标与范围

**做**：uv 工程化、分层骨架、配置单例、结构化日志、错误规范、健康检查、compose 全栈、Alembic 首迁移、CI 四道基础门禁、ADR-0001~0004。

## 2. 技术选型详述

### 2.1 uv（包管理与虚拟环境）

- **是什么**：Astral（ruff 作者）用 Rust 重写的 pip+venv+pip-tools 替代品。
- **为什么**：① 锁文件 `uv.lock` 严格确定性（poetry 锁不严、pip 无锁），CI 与本地依赖逐字节一致；② 并行解析安装，CI 从分钟级降到秒级；③ 2026 年新项目默认解。
- **版本基线**：≥0.5。**用法**：`uv sync`（按 lock 精确装）、`uv add <pkg>`（加依赖并更新 lock）、`uv run pytest`（在环境内执行）。
- **坑**：`uv pip install` 是兼容模式，不走 lock——项目内一律用 `uv sync` / `uv add`。

### 2.2 ruff（Lint + Format）与 mypy（CI 类型门禁）

- **ruff**：单工具替代 black+isort+flake8+pyupgrade，Rust 实现 <1s 全仓检查。配置全部收在 `pyproject.toml`。
- **mypy**：CI 里对 `domain/`、`services/` 开 `strict = true`（路线文档 §4.2 门禁②）；IDE 用 pyright 快反馈。为什么两个都用：IDE 要速度、CI 要严格，单用任何一个都会漏。
- **坑**：SQLAlchemy 2.0 的 `Mapped[]` 声明必须被 mypy 插件识别（`plugins = ["pydantic.mypy", "sqlalchemy.ext.mypy.plugin"]`）。

### 2.3 pydantic-settings（配置单例）

- **是什么**：Pydantic v2 官方配置库，从环境变量 / `.env` 加载并类型校验。
- **为什么**：配置错误在启动时炸（fail-fast），而不是运行到一半才炸；比 `os.getenv` + 手动转型强一个量级。
- **模式**：模块级单例 `settings = Settings()`，全项目唯一入口；测试用 `get_settings()` 工厂 + lru_cache 便于覆盖。

### 2.4 structlog（结构化日志）+ trace_id 中间件

- **是什么**：产出 JSON 行日志（每行一个事件对象，非字符串拼接）。
- **为什么**：M8 要接日志集中与 OTel——JSON 日志是 grep/采集/Loki 的前提；trace_id 必须从中间件注入 contextvar，任何层 `logger.info()` 自动携带。
- **伪代码**见 §3.4。**坑**：uvicorn/access log 默认非 JSON，需关闭原生 access log，用中间件统一记。

### 2.5 RFC 9457 problem+json（错误响应）

- **是什么**：IETF 标准错误体：`{type, title, status, detail, instance, *自定义字段}`，Content-Type `application/problem+json`。
- **为什么**：前端/网关/未来调用方对错误"一个样"；自定义 `{code,msg}` 每家一个样，联调成本高。FastAPI 自定义异常处理器统一包装。

### 2.6 FastAPI app factory + lifespan + 健康检查

- **app factory**：`create_app()` 而非模块级 `app = FastAPI()`——测试可构造不同配置的实例。
- **lifespan**：启动时建 DB/Redis/MinIO 连接池，关闭时释放（替代已废弃的 `on_event`）。
- **/healthz（存活）vs /readyz（就绪）**：healthz 只回答"进程活着"（K8s/compose 重启依据）；readyz 探活依赖（PG `SELECT 1` / Redis `PING` / MinIO `bucket_exists`），任一失败返回 503 + 哪个依赖挂了。**load balancer 摘流量看 readyz，重启看 healthz——两者混淆是生产常见事故源。**

### 2.7 Docker Compose（dev）+ Alembic

- compose 服务：`postgres:17`（含 pgvector 扩展镜像 `pgvector/pgvector:pg17`）、`redis:7.2`、`minio`、`api`。每个服务配 `healthcheck`，api 用 `depends_on: condition: service_healthy` 保证启动顺序。
- Alembic：异步引擎（asyncpg）+ `autogenerate` 生成骨架 + 手工核对。**第一张表 `users`**（含 `password_hash`，argon2 格式占位）。

### 2.8 GitHub Actions 基础四道

`lint(ruff) → type(mypy) → unit(pytest 离线) → build(docker build)`。慢测试用 marker 分层（`-m "not integration"`），集成测试 M1 起再加 testcontainers。

### 3.2 配置单例

```python
# config/settings.py
class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_nested_delimiter="__")

    app_env: Literal["dev", "test", "prod"] = "dev"
    debug: bool = True
    database_url: PostgresDsn          # postgresql+asyncpg://...
    redis_url: RedisDsn
    minio_endpoint: str
    minio_access_key: SecretStr
    llm_api_key: SecretStr | None      # M1 前允许为空
    log_level: str = "INFO"

    @field_validator("database_url")
    def must_use_asyncpg(cls, v):      # 生产坑：同步驱动混入异步栈
        if "asyncpg" not in str(v): raise ValueError("必须使用 asyncpg 驱动")
        return v

settings = Settings()   # 导入即校验，配置错在启动第一秒炸
```

### 3.3 app factory 与 lifespan

```python
def create_app(settings=Settings()) -> FastAPI:
    @asynccontextmanager
    async def lifespan(app):
        app.state.engine = create_async_engine(settings.database_url, pool_size=10, max_overflow=20)
        app.state.redis = Redis.from_url(settings.redis_url)
        yield
        await app.state.engine.dispose(); await app.state.redis.aclose()

    app = FastAPI(title="ContractForge", lifespan=lifespan)
    app.add_middleware(TraceIDMiddleware)
    app.add_exception_handler(AppError, problem_json_handler)   # RFC 9457
    app.include_router(health_router)
    return app
```

### 3.4 trace_id 中间件 + 结构化日志

```python
trace_id_var: ContextVar[str]

class TraceIDMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        trace_id = request.headers.get("X-Request-ID") or uuid4().hex
        trace_id_var.set(trace_id)
        structlog.contextvars.bind_contextvars(trace_id=trace_id)
        t0 = perf_counter()
        resp = await call_next(request)
        # access log 也在结构化通道里，字段：method/path/status/耗时_ms/trace_id/user_id
        log.info("http_access", method=..., status=resp.status_code, cost_ms=...)
        resp.headers["X-Trace-ID"] = trace_id
        return resp

def configure_logging():
    structlog.configure(processors=[
        merge_contextvars, add_log_level, TimeStamper(fmt="iso"), JSONRenderer()
    ])
```

### 3.5 RFC 9457 错误处理

```python
class AppError(Exception):
    status, title, code = 500, "internal", "INTERNAL"

@dataclass
class Problem(Exception):
    status: int; title: str; detail: str; code: str; extra: dict = field(default_factory=dict)

async def problem_json_handler(req, exc: Problem):
    body = {"type": f"https://contractforge.dev/errors/{exc.code}",
            "title": exc.title, "status": exc.status, "detail": exc.detail,
            "instance": str(req.url), **exc.extra}
    log.warning("app_error", code=exc.code, detail=exc.detail)   # 错误必须可观测
    return JSONResponse(body, status_code=exc.status, media_type="application/problem+json")

# 全局兜底：未捕获异常 → 500 problem + 完整 traceback 只进日志、不进响应体（防信息泄露）
```

### 3.6 健康检查

```python
@router.get("/readyz")
async def readyz(request: Request):
    checks = {}
    checks["postgres"] = await _pg_ping(request.app.state.engine)   # SELECT 1, timeout=2s
    checks["redis"]    = await request.app.state.redis.ping()
    checks["minio"]    = await _minio_ping(...)
    unhealthy = [k for k, ok in checks.items() if not ok]
    if unhealthy:
        raise Problem(503, "dependencies unavailable", detail=f"down: {unhealthy}", code="DEP_DOWN",
                      extra={"checks": checks})
    return {"status": "ok", "checks": checks}
```

## 4. 生产复杂性应对（M0 特有）

| 真实情况 | 处理 |
|---|---|
| 新人/新机器环境配置超支 | 风险预案：超 1 天先用 SQLite 兜底跑通骨架，配置债记 M8；`.env.example` 必须能零修改 `cp` 后启动（dev 默认值齐全） |
| 依赖在 CI 与本地漂移 | `uv sync --frozen`；lock 变更必须与 `pyproject.toml` 同 PR |
| 容器半死不活（起着但不接受连接） | 所有依赖服务必须配 healthcheck，api 等健康再启动；readyz 区分"进程在"与"依赖可用" |
| 敏感配置进 git | `.env` 进 `.gitignore`；`llm_api_key` 等 SecretStr 类型，日志渲染自动打码（`***`） |
| 时区问题（服务器 UTC、中国业务 +8） | 日志与 DB 统一存 UTC（`DateTime(timezone=True)`），展示层转东八区；禁止存 naive datetime |
| 未捕获异常泄露内部信息 | 全局兜底：响应体只给 trace_id，堆栈只进日志 |

## 7. 风险与回滚

| 风险 | 缓解 / 回滚 |
|---|---|
| 环境配置超支 | 硬上限 1 天，超了走 SQLite 兜底 |
| uv 与系统 Python 冲突 | uv 自管理 Python 版本（`uv python pin 3.13`），不依赖系统 |
| compose 端口冲突 | `.env` 暴露端口可配；文档注明常用占用（5432/6379/9000） |
