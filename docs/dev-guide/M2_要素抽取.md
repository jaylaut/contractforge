# M2 要素抽取（结构化输出 + 强制溯源）—— 开发指引与验收文档

> 周期 W4 ｜ 主轨 A ｜ 对应架构阶段 C1
> 一句话目标：**把非结构化条款变成可查询、可校验、可溯源的结构化要素——每个字段都必须带 evidence，禁止无溯源的字段入库。**

---

## 1. 目标与范围

**做**：pydantic v2 要素 schema、复用 agentforge LLM 网关（json_schema + 校验 + 重问 + 降级）、长合同分块抽取与归并、evidence 强制、确定性交叉校验、golden set 准确率报表。

**不做**：规则审查（M3）、向量检索、任何"无 evidence 也可信"的字段。

---

## 2. 技术选型详述

### 2.1 复用 agentforge LLM 网关（ADR：不重写）

- 复用能力清单：多 provider 路由、超时/退避重试、三重熔断、token 计费统计、**结构化输出方案**（`response_format=json_schema` 或 `json_object` → pydantic 出站校验 → 失败重问）。
- 集成方式：`pip install -e ../agentforge` 或抽成共享包；本项目只写 `llm/` 里的薄适配层（传 prompt 版本、业务语义字段进 trace）。
- **生产盲区——降级模型能力校验**：降级到小模型时，**先验证其是否真支持 `json_schema` 约束**（部分便宜模型只支持 json_object 甚至纯文本）。不支持则降级路径改为「自由文本 + 更强出站解析（正则 + pydantic 宽松模式）」，而不是静默假设 schema 仍成立。此逻辑进网关适配层。

### 2.2 pydantic v2 严格模型（类型即防线）

- 金额用 `Decimal`（**禁 float**——浮点精度会让"金额一致性校验"变成概率问题）、日期 `date`、币种 ISO 4217 `Literal` 枚举、主体带可选 `unified_social_credit_code`（统一社会信用代码 18 位正则）。
- `model_config = ConfigDict(strict=True, extra="forbid")`：LLM 多吐的字段直接校验失败 → 触发重问，而不是静默吞掉。

### 2.3 evidence 强制（ADR-0006）

每个抽取字段必须带 `clause_id + quote`（原文引文），且 **quote 必须能在原文精确命中（或模糊匹配阈值内命中）**，否则该字段判失败 → `pending_manual`（待人工确认），**绝不静默入库**。这是防 LLM 幻觉的结构性手段：不是"信模型"，而是"模型必须给出可验证的出处"。

### 2.4 分块抽取策略

- 按条款分组切块（不是固定 token 切）：甲乙方/金额/期限集中在首部与价格条款，`违约责任/争议解决` 按标题路由。
- 单块 token 上限（如 4K），超长条款单切；结果归并时**冲突消解**：两块抽到不同金额 → 以确定性交叉校验（原文回查）裁决，裁决不了 → 待人工。

## 3. 详细设计（伪代码级）

### 3.1 数据模型

```sql
CREATE TABLE contract_fields (
    id          UUID PRIMARY KEY,
    contract_id UUID REFERENCES contracts(id),
    field_key   TEXT NOT NULL,        -- party_a / party_b / amount / currency / start_date / end_date
                                  -- / breach_clause / dispute_resolution / special_clauses
    value       JSONB NOT NULL,       -- 类型化后的值
    clause_id   UUID REFERENCES clauses(id),
    quote       TEXT NOT NULL,        -- 原文引文（evidence）
    confidence  REAL NOT NULL,
    status      TEXT NOT NULL DEFAULT 'extracted',   -- extracted/pending_manual/verified
    llm_meta    JSONB                 -- {model, prompt_version, input_tokens, output_tokens, cost}
);
```

### 3.2 要素 schema

```python
class Party(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")
    name: str = Field(min_length=2)
    role: Literal["甲方", "乙方", "丙方"]
    unified_social_credit_code: str | None = None    # 18 位正则校验
    clause_id: UUID; quote: str                       # evidence 强制

class Amount(BaseModel):
    value: Decimal; currency: Literal["CNY","USD","EUR","JPY","GBP","HKD"]
    clause_id: UUID; quote: str

class Extraction(BaseModel):
    parties: list[Party]           # ≥2 才算完整
    amounts: list[Amount]
    start_date: Dated; end_date: Dated       # Dated 同样带 clause_id+quote
    breach_clause: list[ClauseRef]
    dispute_resolution: DisputeRef | None    # 诉讼/仲裁 + 管辖地
    special_clauses: list[ClauseRef]
    incompleteness: list[str]      # 模型自报"哪些字段在提供的文本里找不到"——显式缺口优于幻觉
```

### 3.3 抽取主流程

```python
async def extract(contract_id):
    clauses = await clause_repo.get_all(contract_id)          # M1 产出
    plan = build_block_plan(clauses)     # 按条款语义分组：首部块/价格块/责任块/争议块
    results = await gather_with_semaphore(
        [extract_block(b) for b in plan.blocks], concurrency=3)  # 限流，别打爆配额

    merged, conflicts = merge(results)   # 归并 + 冲突收集
    for f in conflicts + list(iter_fields(merged)):
        ok, checked = cross_validate(f, clauses)   # 确定性交叉校验（不调模型）
        if not ok:
            f.status = "pending_manual"            # 校验不过 → 待人工，绝不静默入库
    await field_repo.save(contract_id, merged)

async def extract_block(block):
    prompt = load_prompt("extract_v3", fields=SCHEMA_HINT, block_text=block.text)
    resp = await llm.chat(
        messages=prompt, temperature=0,
        response_format={"type": "json_schema", "json_schema": ExtractionSchema},
        trace_meta={"contract_id": ..., "prompt_version": prompt.version})
    try:
        parsed = Extraction.model_validate_json(resp.text)     # 出站校验
    except ValidationError as e:
        resp = await llm.reask(resp, errors=e.errors(), retries=2)   # 失败重问 ≤2 次
        parsed = Extraction.model_validate_json(resp.text) if resp else None
    if parsed is None:                       # 两次重问仍失败 → 降级模型
        parsed = await fallback_extract(block, model=SMALLER_MODEL,
                    capability_check=first_probe_json_schema(SMALLER_MODEL))
    return parsed
```

### 3.4 确定性交叉校验（与 LLM 解耦）

```python
def cross_validate(field, clauses) -> bool:
    match field.key:
        case "amount":
            # 1) quote 必须在原文命中（OCR 错字用模糊匹配：ratio ≥ 0.9 视为命中）
            if not fuzzy_locate(field.quote, clauses, threshold=0.9): return False
            # 2) 原文数字回查：quote 所在句子的数字串应包含 field.value
            nums = extract_all_numbers(quote_sentence)
            return normalize(field.value) in {to_decimal(n) for n in nums}
        case "start_date" | "end_date":
            return parses_as_date(field.quote) and field.value == parse_date(field.quote)
        case "party_*":
            return fuzzy_locate(field.quote, ...) and name_count_in_doc(field.value) ≥ 1
```

### 3.5 OCR 错字的 evidence 容错

M1 的 OCR 路径会有错字 → quote 精确匹配会误杀。策略：`rapidfuzz.ratio(quote, 原文候选) ≥ 0.9` 即视为命中，但此时 `confidence *= 0.9` 且 trace 记 `evidence_match=fuzzy`。**阈值宁紧勿松**——错杀去人工，好过错放进库。

## 4. 生产复杂性应对（M2 核心章）

| 真实情况 | 处置 |
|---|---|
| LLM 幻觉金额/日期 | 双保险：evidence 强制 + 原文数字回查；不一致 → `pending_manual`，绝不静默入库 |
| 两次抽取结果不一致 | temperature=0；验收实测两次跑结果一致；仍抖的字段在 M3 转"待人工"而非自动信 |
| 长合同超 token | 按条款分组分块（§2.4）；块间结果冲突走交叉校验裁决 |
| 降级模型不支持 json_schema | 抽取前 probe 能力；不支持 → 自由文本 + 宽松出站解析路径 |
| LLM 服务整体不可用 | 网关熔断生效 → 任务重试排队；连续失败 → 合同标 `extract_failed`，法务仍可读原文（审查流程不瘫痪） |
| OCR 错字导致 evidence 匹配失败 | 模糊匹配阈值 + confidence 折减（§3.5） |
| 合同用了非标结构（要素根本没有） | `incompleteness` 自报缺口 → 落 `pending_manual`，UI 显示"未找到"而非空值假象 |
| 成本失控 | 每次调用记录 token/cost 落库 `llm_meta`；M3/M7 做按合同的限额熔断 |

## 5. 测试计划

- 单测：schema 校验（extra=forbid、Decimal、日期非法值）、merge 冲突消解、cross_validate 各分支、降级 probe 逻辑（mock 网关）。
- 集成：真实网关调 1 份小合同（打标 `@pytest.mark.llm`，CI 手动触发不进默认门禁）。
- 评测：golden set 10 份 → `pytest -m eval`，准确率 < 90% 或较上版降 2pp → 门禁红。

## 6. 验收文档（DoD）

- [ ] 甲乙方 / 金额 / 起止日期 **字段级准确率 ≥ 90%**（证据：`m2_accuracy.md` 报表）
- [ ] **100% 字段带 evidence**，且 quote 能在原文精确/模糊命中（证据：抽查脚本输出）
- [ ] 同一合同抽取两次，结果一致（temperature=0 实测，diff 为空）
- [ ] 单份 20 页合同抽取 P95 ≤ 40s（证据：计时日志）
- [ ] 模型失败时降级重试生效，服务不 500（证据：人为断网/超时演练日志）
- [ ] 校验不过的字段全部 `pending_manual`，无一静默入库（证据：测试用例）

**演示脚本**：一次抽取 → 展示 JSON → 点金额字段 → 原文对应句子被高亮（依赖 M1 坐标）。

**Gate 回写区**：G1 ☐ / G2 ☐ / G3 ☐（准确率回写路线文档）/ G4 ☐。
