# M4 审查报告与前端高亮标注 —— 开发指引与验收文档

> 周期 W7–W8 ｜ 主轨 A ｜ 对应架构阶段 C3
> 一句话目标：**把审查结果变成法务愿意看、看得懂的东西——原文与风险并排，点哪跳哪。前端是本项目从"纯后端"转"全栈"的补全。**

---

## 1. 目标与范围

**做**：不可变报告快照模型、合同/报告/风险/任务四组 API、前端工程化（React 19 + Vite + AntD 5 + TanStack Query + Zustand）、orval 生成 TS client、三栏布局与高亮交互、Playwright E2E。

**不做**：PDF 渲染引擎自研（用 pdf.js / 页图方案）、移动端适配、多语言、复杂权限 UI（M5）。

---

## 2. 技术选型详述

### 2.1 报告快照（不可变版本化）

- **设计**：`review_reports(id, contract_id, version, snapshot JSONB, created_at)`，重审生成 **version+1 新记录**，旧版本只读。
- **为什么**：审批流引用的报告必须是审批那一刻的快照——事后重审不能改写历史，否则"可追溯、可审计"崩塌。风险明细不直接查 findings 表（会被后续操作改），从 snapshot 还原。
- snapshot 内容：findings 全量 + 统计（各等级数量）+ 审查元信息（prompt 版本、模型、耗时、是否降级）。

### 2.2 前端栈（2026 企业中后台事实标准）

| 选型 | 为什么 | 淘汰了什么 |
|---|---|---|
| React 19 + TypeScript 严格模式 | 生态最深、类型即契约 | Vue：团队背景是 React 岗位 |
| Vite 7 | 秒级冷启动、HMR | webpack 脚手架已淘汰 |
| Ant Design 5 | 表格/表单/审批流组件开箱即用，中后台事实标准 | Material UI：中后台组件不全 |
| TanStack Query v5 | **服务端状态**：缓存/重试/失效/轮询内建 | 手写 axios + useState 地狱 |
| Zustand | **客户端状态**（当前选中风险、视图偏好）：轻、无样板代码 | Redux：样板代码多 |
| orval | **OpenAPI → TS client 生成**：后端改字段前端编译期报错 | 手写 axios：必然漂移 |
| Playwright | E2E 无头浏览器，CI 可跑 | Cypress：多标签/多窗口场景弱（M5 要双窗口并发测试） |

**状态分界铁律**：来自 API 的一切数据归 TanStack Query（不进 Zustand）；Zustand 只放 UI 态。混放是前端烂掉的头号原因。

### 2.3 高亮标注的坐标体系（本项目前端核心难点）

- 统一用 M1 的**页宽高归一化坐标**（0~1）。前端渲染分两个视图：
  1. **页图视图**（主）：后端渲染页图（文本型 PDF 转图 / OCR 栅格图），HTML 层按 `bbox * 渲染尺寸` 绝对定位画高亮 div——坐标换算简单可靠；
  2. **文本视图**（兜底）：纯 HTML 文本流 + `<mark>` 高亮（char_start/char_end），任何解析形态都可用，OCR/降级场景保证不白屏。
- 先做文本视图兜底，再加页图视图——风险预案（坐标与渲染不一致是最大风险）。

## 3. 详细设计（伪代码级）

### 3.1 API 契约（本里程碑全部只读 + 报告生成）

```
GET  /api/v1/contracts?status=&page=&size=        → 分页列表（含 parse/review 状态）
GET  /api/v1/contracts/{id}                       → 详情
GET  /api/v1/contracts/{id}/report?version=latest → 报告快照（findings + 统计）
POST /api/v1/contracts/{id}/review                → 触发重审（异步，202+task_id）
GET  /api/v1/tasks/{task_id}                      → 任务状态 {state, progress, error?}
GET  /api/v1/contracts/{id}/pages/{n}.png         → 页图（高亮底图）
```

### 3.2 三栏布局

```
┌──────────────────┬────────────────────┬──────────────────┐
│ 左：原文视图        │ 中：风险列表          │ 右：建议与操作       │
│ 页图+高亮层 / 文本流 │ 按等级分组 blocker…   │ 单条风险详情        │
│ 点风险→滚动定位高亮  │ 点条目→左栏定位        │ 接受/忽略/转人工     │
│ 点原文→反向筛选风险  │ 搜索/按规则筛选        │ basis + suggestion │
└──────────────────┴────────────────────┴──────────────────┘
```

### 3.4 高亮渲染（页图视图）

```tsx
function HighlightLayer({ page, findings, containerSize }) {
  // 归一化坐标 × 实际渲染尺寸 —— 服务端不需要知道前端像素
  return findings.filter(f => f.bbox?.page === page).map(f => (
    <div key={f.id} className={`hl hl-${f.level}`} style={{
      left: f.bbox.x0 * containerSize.w, top: f.bbox.y0 * containerSize.h,
      width: (f.bbox.x1 - f.bbox.x0) * containerSize.w,
      height: (f.bbox.y1 - f.bbox.y0) * containerSize.h }}
      onClick={() => select(f.id)} />));
}
// bbox 缺失（DOCX 降级）→ 自动切文本视图并提示"该文档为段落级定位"
```

## 4. 生产复杂性应对（M4 核心章）

| 真实情况 | 处置 |
|---|---|
| PDF 坐标与浏览器渲染不一致 | 唯一坐标系 = 页宽高归一化；前端按实际渲染尺寸换算；文本视图兜底，页图视图增强 |
| OCR/DOCX 降级形态没有精确 bbox | 前端按 `parse_confidence`/bbox 有无自动选视图；缺 bbox 不报错，显示段落级定位 |
| 100 条风险的报告页卡顿 | 风险列表虚拟滚动（AntD `virtual`）；页图懒加载；首屏 < 1.5s 验收 |
| 接口失败/断网 | TanStack Query 重试 + 空态/错误态组件，**不白屏**；全局 ErrorBoundary |
| 重审后旧报告被引用 | 报告不可变快照（§2.1）；审批流（M5）持快照 id，天然免疫 |
| 双人同时看同一报告，一人点了"忽略" | M4 阶段 UI 态只本地（暂不做协同）；M5 起风险处置状态进 DB + 乐观锁 |
| 浏览器兼容（企业内网老 Chrome） | Vite 构建 target es2020；AntD 5 官方支持范围；E2E 跑 chromium |

## 7. 风险与回滚

| 风险 | 缓解 / 回滚 |
|---|---|
| 坐标渲染始终对不齐 | 回退文本视图（char offset 高亮）先交付；页图视图作为增强迭代 |
| orval 生成器 bug/升级破坏 | 生成物提交 git（可 review、可回滚）；生成器版本锁死 |
| AntD 5 定制深度超预期 | CSS-in-JS token 定制优先；实在不行评估 Arco（同为字节系中后台组件库） |
| 前端工作量爆炸挤占后端 | 保底形态 = 只读报告页（无接受/忽略交互）；交互增强放 M5 之后 |
