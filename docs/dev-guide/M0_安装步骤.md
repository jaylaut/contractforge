## 一、依赖审计结论（requirements.txt 核对结果）

先给结论：**requirements.txt 可以把依赖装起来，但它不是当前唯一的坑——`pyproject.toml` 本身是空壳**。逐项核对如下。

### 1.1 发现的问题（按严重程度排序）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| ① | **`pyproject.toml` 没有 `[project.dependencies]` 段**，`pip install -e .` / `uv sync` 实际**装不到任何第三方依赖** | 路线文档写的 `pip install -e .`（README §快速开始）是空操作；requirements.txt 成为唯一生效的依赖源，与"uv.lock 单一事实源"的 M0 目标矛盾 | 把依赖迁入 `pyproject.toml`（`uv add` 逐个加），`requirements.txt` 降级为兼容入口（`uv pip compile` 自动生成，不再手维护） |
| ② | **M0 必需的依赖在 requirements.txt 中缺失**：`structlog`（结构化日志）、`alembic`（迁移）、`minio`（对象存储客户端）、`ruff`、`mypy`、`pytest-cov`（工具链） | M0 的日志/健康检查/迁移/CI 四道门禁装不上 | 见 §2.2 的「M0 需要新增」清单 |
| ③ | `paddleocr>=2.7` / `paddlepaddle>=2.6` 放在主依赖里 | 属于 **M1** 的能力；paddlepaddle 与 numpy 版本强绑定，M0 就装会拖死/冲突整个环境 | 拆到 `[dependency-groups] ocr = [...]`（uv 支持 group 不默认安装），M1 再 `uv sync --group ocr` |
| ④ | `requires-python = ">=3.12"`、`[tool.ruff] target-version = "py312"`、`mypy python_version = "3.12"` | 与路线文档的 **Python 3.13 基线**不一致（3.12 能跑但不是基线；3.14 生态未验证） | 统一升到 `>=3.13` / `py313`（或明确降基线为 3.12 并写进 ADR，二选一，不要两处说法不一） |
| ⑤ | `opentelemetry-instrumentation-fastapi>=0.44b0` 是 beta 版本号写法 | `>=0.44b0` 的比较语义容易在 PEP 440 下产生意外匹配 | 正式发版后锁 `>=0.44`（M0 只需 api+sdk，instrumentation 可延后到 M8 前再装） |
| ⑥ | agentforge 以 `-e ../rag/agentforge` 注释行存在，路径未确认（`../rag/agentforge` 相对本仓库不存在） | M2 才真正用到；M0 可不装 | M0 不装；M2 开工前确认本地路径后以 editable 引入 |
| ⑦ | `locust`（M7）、`kafka/confluent-kafka`（M6）、`testcontainers/polyfactory/hypothesis`（测试三件套）均未列出 | M0 不需要，但路线文档的技术基线里有 | 不加进 M0；在各里程碑开工时随 `uv add` 引入，避免"装了不用" |

### 1.2 requirements.txt 与 M0 需求的逐条判定

| requirements.txt 条目 | M0 是否需要 | 备注 |
|---|---|---|
| pdfplumber / python-docx / paddleocr / paddlepaddle | ❌（M1） | paddle 系建议拆 group（问题③） |
| httpx | ✅ 需要但非阻塞 | healthz 探活 MinIO 可先用官方 `minio` 包；httpx 是 M2 网关用的，M0 装上无害 |
| pydantic / pydantic-settings / python-dotenv | ✅ | Settings 单例（M0 文档 §3.2）依赖三者；`pydantic-settings` 自带 .env 读取，`python-dotenv` 可留可去 |
| sqlalchemy / asyncpg / pgvector | ✅（pgvector 本里程碑暂用不到） | engine/session 工厂 + Alembic 都要 sqlalchemy+asyncpg；pgvector 是 M2/M8 向量检索用，可留 |
| arq / redis | ✅（arq worker M0 可不启动） | redis 连接是 `/readyz` 三依赖之一，必装；arq 装上，任务从 M1 起真正使用 |
| opentelemetry-* / prometheus-client | ⏸ 可延后 | M0 只要求 JSON 日志，OTel 全面接入在 M8；可装 api+sdk 不接 exporter，或干脆 M8 再加 |
| fastapi / uvicorn[standard] / python-multipart | ✅ | 核心服务；multipart 是 M1 上传才用，装上无害 |
| PyJWT / argon2-cffi | ✅（仅建 `users` 表占位） | 选型已对（替代 passlib/python-jose），M0 只落依赖与表结构，不实现登录 |
| pytest / pytest-asyncio | ✅ | 测试基座；建议补 `pytest-cov`（CI 覆盖率口径统一） |

### 1.3 M0 需要新增的依赖（最小集）

```text
structlog>=24        # JSON 结构化日志（M0 验收硬指标）
alembic>=1.13        # 迁移（0001_users）
minio>=7.2           # MinIO S3 客户端（readyz 探活 + M1 上传）
ruff>=0.8            # Lint/Format（make check + CI 门禁①）
mypy>=1.11           # 类型门禁（CI 门禁②）
pytest-cov>=5.0      # 覆盖率口径
```

> 若走 uv 路线：以上用 `uv add structlog alembic minio` + `uv add --dev ruff mypy pytest-cov` 完成，自动写进 `pyproject.toml` 并生成 `uv.lock`。

## 二、安装步骤（按顺序执行，每步有验证）

> 双轨设计：**主轨 = uv**（M0 目标形态，`uv.lock` 入库）；**兼容轨 = requirements.txt**（先用它把环境立起来，再逐步迁移）。两轨不要混着当日常用法，选一条作为主用法。

### 步骤 0：环境预检

```bash
python3 --version    # 期望 ≥ 3.13（路线文档基线）；本机有 3.13.12 即满足
docker --version     # 期望 Docker Desktop / Engine 可用，docker compose version ≥ v2.20
docker info          # 确认 daemon 在跑
```

- 无 uv 则先装（官方脚本走 GitHub 不可达的网络环境时，用 `pip install uv` 走 PyPI 镜像即可）：

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple uv
uv --version         # 期望 ≥ 0.5
```

- **网络提示**（本机已验证的网络约束）：GitHub 直连不可达；PyPI 走清华 TUNA 镜像可达。给 uv/pip 配镜像：

```bash
export UV_DEFAULT_INDEX="https://pypi.tuna.tsinghua.edu.cn/simple"
export UV_HTTP_TIMEOUT=120
```

### 步骤 1：创建虚拟环境并固定 Python 版本

```bash
cd /Users/jayl/LLM/contractforge
uv python pin 3.13          # 生成 .python-version
uv venv                     # 创建 .venv（uv 自动下载 3.13，不依赖系统 Python）
source .venv/bin/activate   # 或后续全部用 `uv run` 前缀
```

验证：`uv run python --version` → `3.13.x`。

### 步骤 2：安装依赖（二选一）

**主轨（推荐，M0 的最终形态）**——直接把依赖写进 pyproject：

```bash
# 运行时依赖（requirements.txt 中 M0 需要的部分 + 审计新增）
uv add "fastapi>=0.115" "uvicorn[standard]>=0.30" "python-multipart>=0.0.9"
uv add "pydantic>=2.9" pydantic-settings
uv add "sqlalchemy>=2.0" "asyncpg>=0.29"
uv add "redis>=5.0" arq
uv add structlog alembic minio
uv add PyJWT "argon2-cffi>=23.1"

# 开发/工具链依赖（dev group，不进生产镜像）
uv add --dev ruff mypy pytest pytest-asyncio pytest-cov
```

**兼容轨（过渡用）**——按 requirements.txt 装，再补审计缺口：

```bash
uv pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
uv pip install structlog alembic minio ruff mypy pytest-cov
```

> ⚠️ 兼容轨会一并装上 paddleocr/paddlepaddle（M1 才用，版本绑定较重）。若只求 M0 轻量启动，临时把这两行注释掉再装。
> 无论哪条轨：**不要**用 `pip install -e .` 当作"装依赖"——审计问题①：pyproject 目前无 dependencies，它什么都装不上。

### 步骤 3：补齐 pyproject 工程配置（执行者自建）

- `[project.dependencies]`：主轨已在步骤 2 自动写入；兼容轨需手工把 §1.3 清单补进去，否则 `uv.lock` 与环境继续脱节。
- `[tool.pytest.ini_options]` 增补 marker 分层（CI 用）：

```toml
markers = [
    "integration: 依赖外部服务（PostgreSQL/Redis/MinIO）的集成测试",
    "llm: 会真实调用 LLM 的测试，CI 默认跳过",
    "eval: golden set 评测回归（M2 起）",
]
```

- `[tool.mypy]`：M0 骨架阶段可维持现状（strict=false）；路线文档要求 M3 前 `domain/`、`services/` 目录级 strict（`[[tool.mypy.overrides]]`），此处先记入待办。

### 步骤 4：基础设施（docker compose）

按 M0 文档 §3.7 自建 `docker-compose.dev.yml`（postgres:17 + pgvector / redis:7.2 / minio，**每个服务必须配 healthcheck**），然后：

```bash
cp .env.example .env        # .env.example 由执行者自建，内容对齐 M0 文档 §3.2 的 Settings 字段
docker compose -f docker-compose.dev.yml up -d
docker compose -f docker-compose.dev.yml ps   # 三个基础服务均应 healthy
```

验证（绕过应用直连测依赖）：

```bash
docker compose -f docker-compose.dev.yml exec postgres pg_isready -U postgres   # accepting connections
docker compose -f docker-compose.dev.yml exec redis redis-cli ping              # PONG
curl -s http://localhost:9000/minio/health/live                                 # 200
```

### 步骤 5：数据库迁移（0001_users）

```bash
uv run alembic init alembic                # 首次；随后改 env.py 为 async 引擎（M0 文档 §2.7）
uv run alembic revision --autogenerate -m "create users"
uv run alembic upgrade head
```

验证：`psql` 连库 `\d users` 看到表；`alembic history` 有版本链。

### 步骤 6：应用启动与健康检查

按 M0 文档 §3.3–3.6 自建 `create_app()` / 中间件 / `/healthz` `/readyz` 后：

```bash
uv run uvicorn contractforge.api.app:create_app --factory --reload --port 8000
curl -s localhost:8000/healthz      # 200
curl -s localhost:8000/readyz       # {"postgres":true,"redis":true,"minio":true}
curl -s localhost:8000/docs         # OpenAPI 可开
```

### 步骤 7：质量门禁自检

```bash
uv run ruff check . && uv run ruff format --check .
uv run mypy src/contractforge
uv run pytest -m "not integration"
```

三项全绿后，按 M0 文档 §6 的 DoD 逐项打勾（CI 配置与 ADR-0001~0004 也在那份文档里）。

## 三、常见安装问题速查

| 症状 | 原因与处置 |
|---|---|
| `pip install -e .` 后 import fastapi 报 ModuleNotFoundError | 审计问题①：pyproject 无 dependencies。改用步骤 2 任一轨道 |
| `uv sync` 报 lock 与 pyproject 不一致 | 先 `uv lock`（或 `uv sync` 时去掉 `--frozen`）更新锁；lock 变更须与 pyproject 同次提交 |
| paddlepaddle 与 numpy 版本冲突 | 拆 group：`uv add --group ocr paddleocr paddlepaddle`，M0 不装该 group |
| uv 下载超时 | 确认 `UV_DEFAULT_INDEX` 指向 TUNA；或临时 `pip install -i https://pypi.tuna.tsinghua.edu.cn/simple ...` 兜底 |
| MinIO readyz 失败但容器 healthy | bucket 未创建或 access key 未配；healthcheck 只保证进程活着，readyz 校验的是"能不能用"——这正是二者分开的意义 |
| asyncpg 连接报 `password authentication failed` | `.env` 的 `DATABASE_URL` 与 compose 里 PG 初始化变量不一致；compose 卷已初始化后改密码无效，需 `docker compose down -v` 重来（会清数据，dev 环境可接受） |

本机（macOS 27 / M1）已装好 Docker 运行时，步骤 4 的 `docker compose` 可直接执行：

| 组件 | 版本 | 安装方式 |
|---|---|---|

| docker-compose | 2.39.2 | 同上，已软链 `~/.docker/cli-plugins/docker-compose` |
| VM | vz 虚拟化，4C/6G/60G，virtiofs | `colima start --vm-type vz --cpu 4 --memory 6 --disk 60` |

已处理的网络适配（本机 GitHub / Docker Hub 直连不可达）：

1. **colima VM 镜像**：预置到 `~/Library/Caches/colima/caches/<sha256(下载URL)>`（注意：Go 的 UserCacheDir 在 macOS 是 `~/Library/Caches` 不是 `~/.cache`），sha512 与 colima 内嵌期望值比对通过，启动不再联网。
2. **registry mirror**：写入 VM 内 `/etc/docker/daemon.json`（`LIMA_HOME=~/.colima/_lima limactl shell colima -- sudo tee /etc/docker/daemon.json`），mirrors = 1panel / 1ms / xuanyuan。`docker pull postgres:17` 等常规拉取自动走 mirror，compose 文件无需改镜像名。

日常运维速查：

```bash
colima status          # VM 状态
colima stop / start    # 停止/启动（VM 磁盘持久化）
colima delete          # ⚠️ 删 VM 与全部容器/卷
docker compose up -d   # 起本项目 dev 基础设施（步骤 4）
```
