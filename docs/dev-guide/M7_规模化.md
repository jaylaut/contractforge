# M7 规模化：压测 · 限流 · 数据治理 —— 开发指引与验收文档

> 周期 W13–W14 ｜ 主轨 C（债务阶段 2–3）
> 一句话目标：**先造压力，再让优化长出来；每个优化都有前后数字。**
> ⚠️ 量级诚实性：100 万合同是**压力目标与推演叙事**，不是"单机 32G 真存 100 万份原文"。逻辑正确性用可承受数据量（10–50 万）实测验证；量级叙事用「分片扩展性推演 + 单分片实测」证明。

---

## 1. 目标与范围

**做**：数据灌库脚本（批量 COPY）、Locust 三场景压测与容量基线、网关令牌桶限流、LLM 熔断降级、连接池调优、pg_stat_statements 慢查询治理、按月分区、冷热分离归档、Redis 读缓存。

**不做**：真分库分表（单机做分区 + 按租户分片的**设计与推演**，落地要真多机）、读写分离主从（设计 + ADR，量级不配）、K8s。

## 2. 技术选型详述

### 2.1 Locust（压测）

- Python 写压测脚本（可直接复用 API client 代码），三场景独立 user class：上传（含文件 IO）/ 列表查询（读多）/ 审批提交（写+并发冲突）。
- **方法论**：先测基线（无优化）→ 记录 QPS/P50/P95/P99/错误率/CPU/内存 → 逐项优化 → 复测对比。**没有基线的优化是自嗨。**
- 单机压测的局限：Locust 与被压系统同机互相抢 CPU——数字只用于**相对对比**，不吹绝对 QPS（面试话术也是这么讲）。

### 2.2 限流：令牌桶（网关层 + 应用层双保险）

- **网关层**（Nginx `limit_req`）：按 IP/全局粗粒度，防扫防爬。
- **应用层**（Redis 令牌桶，`redis-py` Lua 原子脚本）：按用户 + 按 API 组精细控——特别是 **LLM 相关接口单独配额**（防"防突发流量打爆 LLM 账单"）。
- 超限返回 **429 + `Retry-After`**（RFC 标准），前端有对应提示。

### 2.3 熔断与降级

- 复用 agentforge 三重熔断（错误率/慢调用/并发数），接真实场景：LLM 下游超时 → 审查任务退化为"仅规则通道"（M3 已有降级路径，这里自动触发）+ 前端提示"语义审查延迟"。
- DB 慢 → 查询超时设置（`statement_timeout`）防止连接池被慢查询耗尽 → 级联雪崩。

### 2.4 慢查询治理方法论

```
pg_stat_statements 开启 → 按 total_time 排 Top10 → EXPLAIN (ANALYZE, BUFFERS)
  → 典型病灶：缺复合索引 / LIKE '%x%' 全表扫 / OFFSET 深分页 / N+1
  → 对症：索引 / 前缀匹配+全文检索 / keyset 分页 / 预加载
  → 每条优化记录前后对比数字（写入压测报告）
```

### 2.5 分区与冷热分离

- `contracts` 按 `created_at` **按月 RANGE 分区**（PG 原生，零额外组件）；查询必带时间或走分区键（分区裁剪）。
- 冷数据（>1 年）：**原文归档 MinIO 冷桶 + 元数据保留 PG**（合同列表仍可查可搜，原文按需从冷桶取回）；归档任务**可重入**（按批次 idempotent，中断续跑）。
- 为什么不现在分库分表：单机 32G + PG17，分区已解决"老数据拖慢新查询"；分库要改连接拓扑，量级不配——**设计进 ADR，落地看触发条件**。

### 2.6 Redis 读缓存（cache-aside + 先删后更）

- 缓存对象：合同列表页（按用户+筛选条件 hash 作 key）、报告快照。
- 一致性策略：**写后先删缓存再更库**（简单可解释；配合短 TTL 兜底，不用复杂双删）。读场景低一致性要求，可接受秒级陈旧。

### 3.2 限流器（Redis Lua 原子令牌桶）

```lua
-- tokens: 桶内令牌; ts: 上次时间。原子性防竞态（不用 GET+SET 两步）
local rate, capacity = tonumber(ARGV[1]), tonumber(ARGV[2])
local now = tonumber(ARGV[3]); local key = KEYS[1]
local t = redis.call('HMGET', key, 'tokens', 'ts')
local tokens = math.min(capacity, tonumber(t[1]) or capacity) - (now - (t[2] or now)) * rate
if tokens < 1 then return 0 end
redis.call('HMSET', key, 'tokens', tokens - 1, 'ts', now)
redis.call('EXPIRE', key, 3600); return 1
```

```python
async def rate_limit(user_id, scope):
```

### 3.3 深分页治理（列表查询典型慢源）

```sql
-- 反面：OFFSET 1000000 LIMIT 20  → 扫 100 万行
-- 正面：keyset 分页（游标 = created_at + id 复合索引）
```

## 4. 生产复杂性应对（M7 核心章）

| 真实情况 | 处置 |
|---|---|
| 压测打崩本机 | 限流参数先用保守值；压测低峰跑；Locust step-load 逐步加压（不是一把 1000 并发） |
| 100 万数据灌不完/灌爆磁盘 | 元数据灌 100 万，**原文不真灌**（object_key 指向少量真实样本）；COPY 批量 + 分区表先建后灌 |
| 缓存击穿（热点 key 过期瞬间打穿 DB） | 单飞锁（Redis setnx 只放一个请求回源）；TTL 加随机抖动 |
| 缓存与 DB 不一致 | 先删缓存再更库 + 短 TTL；列表场景容忍秒级陈旧 |
| 归档任务中断产生半归档 | 批次 marker + 冷桶 copy 原子校验（存在才删热）；断点续跑 |
| 分区误设计导致查询不裁剪 | 强制分区键过滤（查询规范进 code review checklist）；EXPLAIN 验证 partition pruning |
| LLM 配额被单租户打爆 | 按用户限流 + 按合同 token 预算（`llm_meta` 汇总），超预算熔断 |
| 压测数据污染生产数据集 | 灌库前 snapshot；测试库/标签隔离（seed 数据 `is_seed=true` 可一键清除） |

## 6. 验收文档（DoD）

- [ ] 100 万元数据下列表查询 P95 < 200ms（给出优化前 ~3s 的对比）（证据：压测报告）
- [ ] 1000 并发下错误率 < 1%，限流生效且返回 429 + `Retry-After`（证据：Locust + Grafana）
- [ ] LLM 下游超时，接口自动降级为"仅规则 + 稍后补语义"，不级联雪崩（证据：熔断演练日志）

## 7. 风险与回滚

| 风险 | 缓解 / 回滚 |
|---|---|
| 优化把正确性改坏 | 每项优化有回归测试；keyset 分页有兼容旧 offset API 的过渡参数 |
| 分区迁移锁表 | expand-contract：新分区表双写 → 切读 → 删旧；低峰执行 |
| 压测报告数字无法复现 | 脚本化压测（Locust 文件入库）+ 环境参数记录，可重跑 |
| 缓存引入后问题更难查 | 全缓存读写打 trace（hit/miss 标记）；可一键禁用缓存回退直查 |
