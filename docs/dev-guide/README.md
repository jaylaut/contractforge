## 三、通用工程规范（所有里程碑共用）

### 3.1 技术栈基线（详见架构文档 §四 与路线文档 §2.1，此处只列每里程碑要用的最小集）

| 类别      | 选型                                                                  | 备注                                      |
| ------- | ------------------------------------------------------------------- | --------------------------------------- |
| 语言/包管理  | Python 3.13 + **uv**（≥0.5）                                          | `uv.lock` 入库；pip/poetry 淘汰              |
| Lint/类型 | ruff（≥0.8）+ mypy（CI 严格）                                             | IDE 侧 pyright 快反馈                       |
| Web     | FastAPI ≥0.115 + Pydantic v2 + uvicorn                              | RFC 9457 错误体                            |
| ORM/迁移  | SQLAlchemy 2.0 async + asyncpg + Alembic                            | 迁移走 expand-contract                     |
| 数据库     | PostgreSQL 17 + pgvector 0.8；Redis 7.2；MinIO（S3 协议）                 | PG 是唯一事实源                               |
| 任务队列    | M1–M5：arq（Redis）→ M6 迁移 Kafka 4.x（KRaft）                            | ADR-0004                                |
| 认证      | PyJWT + `argon2-cffi`                                               | **禁用 passlib / python-jose（停维护/有 CVE）** |
| 日志/可观测  | structlog（JSON）→ M8 全量 OTel + GenAI semconv                         | trace_id 全程贯穿                           |
| LLM 网关  | 复用 agentforge（重试/降级/计费/结构化输出）                                       | 不引入 LangChain/LlamaIndex（ADR-0001）      |
| 向量      | Qwen3-Embedding-0.6B + Qwen3-Reranker-0.6B【演进叙事】                    | 本地推理不出域（ADR-0009）                       |
| 前端      | React 19 + TS + Vite 7 + AntD 5 + TanStack Query v5 + Zustand       | orval 生成 TS client                      |
| 测试      | pytest + testcontainers + polyfactory + hypothesis + Playwright     | 不 mock 数据库                              |
| CI      | GitHub Actions 七道门禁（ruff/mypy/unit/integration/eval/security/build） | 任一红灯不许合并                                |

### 3.2 分层与依赖方向（代码结构铁律）

```
api/  →  services(业务)  →  domain(纯逻辑，零外部依赖)  →  storage/
                       ↘ llm/  ↘ tasks/
```

- `domain/` 不允许 import FastAPI、SQLAlchemy、httpx——保证规则引擎/状态机等纯逻辑离线可测。
- 跨层只能向下依赖，禁止反向（storage 不得 import api）。
- 接口契约：`api/routes` 只做鉴权/校验/入队编排，不写业务规则。

### 3.3 分支与提交

- Trunk-based：`main` 常绿；功能分支 ≤ 2 天生命周期；Conventional Commits（`feat(m3): ...`）。
- PR 自审四问：变更说明 / 影响面 / 如何验证 / 回滚方式。禁止直接推 main、禁止 `--no-verify`。

### 3.4 数据库演进（expand-contract）

1. **Expand**：加新表/新列（可空/带默认）→ 发布 → 双写或回填；
2. **Contract**：确认无旧读依赖后，下个发布再删旧结构。禁止一步到位的破坏性迁移。

### 3.5 AI 工程规范

- prompt 文件化 + 版本号（`prompts/extract_v3.md`），trace 记录 prompt 版本；禁止硬编码在代码里。
- 结构化输出三件套：`json_schema` 约束 → pydantic 出站校验 → 失败重问 ≤ 2 次 → 降级模型（降级前先验证其 schema 能力）。
- 每次调用记录：模型名、token 数、耗时、成本、prompt 版本、trace_id。
- 合同敏感：**本地解析/OCR/嵌入不出域**；远程 LLM 只传必要条款文本，不做全篇外发。

### 3.6 验收通用 Gate（每个里程碑结束过一遍）

| Gate  | 判定                                           | 不合格的处置        |
| ----- | -------------------------------------------- | ------------- |
| G1 能跑 | `docker compose up` 起得来，本里程碑主链路可当场演示         | 停下补，不带病前进     |
| G2 可测 | 新增核心逻辑单测 ≥ 80%，CI 全绿，本地 `make check` 与 CI 同源 | 补测试，禁止"先合并后补" |
| G3 可证 | 量化数据（准确率/P95/成功率）写回路线文档                      | 没有数据 = 没做完    |
| G4 可读 | README / 接口文档 / ADR 同步更新                     | 文档缺失算未完成      |

### 3.7 DoD 模板（各里程碑验收区共用的填写格式）

```markdown
- [ ] <可当场验证的一句话> （证据：<命令/截图/报表/测试名>）
```

## 四、生产复杂性总纲（各里程碑 §4 的共同底层逻辑）

真实生产环境的复杂性来自四个不确定性，每个里程碑的 §4 都映射到其中若干项：

| 不确定性      | 典型表现                        | 项目内的落点                           |
| --------- | --------------------------- | -------------------------------- |
| **输入不确定** | 扫描件/加密 PDF/表格魔幻版式/旧 .doc    | M1 降级矩阵、格式探测                     |
| **模型不确定** | 幻觉金额、两次结果不一致、降级模型不支持 schema | M2 evidence 强制、M3 伪确定性点破、M3 降级路径 |
| **时间不确定** | 长任务 30s~几分钟、审批跨天卡死、并发同时点通过  | M2/M3 异步化、M5 超时催办/重入/乐观锁         |
| **规模不确定** | 量级突然上来、LLM 账单打爆、队列堆积        | M6 Kafka 削峰、M7 限流熔断/分区归档         |

**设计立场**：不追求"预测所有情况"，而是保证——① 任何输入都有明确出路（成功/降级/阻断，绝不静默）；② 任何失败都有重试与兜底；③ 任何状态变化都可追溯可回滚。
