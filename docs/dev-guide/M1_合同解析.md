# M1 合同解析与条款结构化（含 OCR）—— 开发指引与验收文档

> 周期 W2–W3 ｜ 主轨 A ｜ 对应架构阶段 C0
> 一句话目标：**一份真实 PDF/Word/扫描件合同，稳定抽出正文、表格、条款结构，且每个字都有坐标（文本层或 OCR 层）。坐标是全系统的承重墙——M2 溯源、M3 定位、M4 高亮全部建立在它之上。**

---

## 1. 目标与范围

**做**：上传接口（MinIO + contracts 记录）、格式探测 detector、三个解析器（pdf/docx/ocr）、条款切分、坐标归一化、加密 PDF 阻断、10 份真实样本集。

**不做**：任何 LLM 调用（M2）、OCR 模型训练/微调、手写签名识别、逐像素版式还原。

## 2. 技术选型详述

### 2.1 pdfplumber（文本型 PDF 主解析器）

- **是什么**：基于 pdfminer.six 的封装，能提取**词级坐标** `word → (page, x0, y0, x1, y1)`、表格线、字符流。
- **为什么**：① 唯一纯 CPU 且**带词级坐标**的易用方案——坐标是高亮标注/溯源的基础；② 表格提取（`extract_tables`）能拿到线框表格。
- **为什么不用 pypdf**：提取质量一般、无坐标。**为什么不用 PyMuPDF（fitz）**：AGPL 许可对企业商用有传染风险（项目可标注合规决策，若个人学习可选，但 ADR 建议避开）。
- **坑**：① 中文 PDF 常见 CID 字体（无 Unicode 映射）→ 抽出乱码，需检测乱码率并转 OCR 路径；② 双栏/盖章压字版式行序错乱 → 按 y 轴聚类重建行。

### 2.2 python-docx（DOCX 解析）+ LibreOffice headless（坐标补齐）

- **DOCX 是流式格式，没有页坐标**——这是隐蔽坑。两条路：
  1. **转 PDF 对齐**（主路径）：`libreoffice --headless --convert-to pdf` 后用 pdfplumber 取坐标，段落文本与 PDF 行做**文本对齐**（difflib 序列匹配），段落级坐标 → 行级坐标；
  2. 段落序号降级定位（转换失败时，`parse_confidence` 标低）。
- **为什么不用 docx2pdf**：依赖本机 Word（Windows only）；LibreOffice headless 跨平台可容器化（`lscr.io/linuxserver/libreoffice` 或直接 apt 安装）。
- **坑**：LibreOffice 转换会**重排**版式 → 文本对齐必须容忍换页/换行差异；旧 `.doc`/`.wps` 同样走此转换通道（先转 docx/pdf 再解析）。

### 2.3 PaddleOCR（扫描件/图片，**主线能力非演进**）

- **为什么是主线**：盖章件/传真件/拍照件在真实法务场景占比最高；合同敏感 → 必须**本地推理不出域**，云 OCR（百度/腾讯）是合规红线，不选。
- **为什么选 PaddleOCR**：中文识别效果开源第一梯队；PP-OCRv4/v5 支持 `det`（检测框 bbox）+ `rec`（识别）+ 表格结构；Apache 2.0。
- **部署形态**：CPU 推理（M1 起）用 paddlepaddle CPU 版或导出 onnx 跑 onnxruntime（依赖更轻）。**坑**：paddlepaddle 与 numpy 版本强绑定，装在独立 uv dependency group（`[dependency-groups] ocr = [...]`），必要时独立容器 `ocr-worker` 隔离。
- **路径触发**：页均字符数 < 阈值（如 50 字/页）的 PDF 自动判为扫描型 → OCR 路径。
- **精度事实**：OCR bbox 精度天然低于原生文本层——这不是 bug，验收按形态分开定标准（文本型画框命中 100%，OCR 型 ≥95% 且在视觉容差内）。

### 2.4 格式探测 detector

判定顺序（伪代码见 §3.3）：文件魔数/扩展名 → PDF 加密探测（pypdf `is_encrypted`）→ PDF 页均字符密度（文本型 vs 扫描型）→ DOCX/DOC/WPS/图片分派。**探测结果落库 `source_format` + `parse_confidence`，下游一切精度预期以此为准。**

### 2.5 clause_splitter（条款切分）

识别五类编号：`第X条`（含汉字数字）、`一、`、`（一）`、`1.1`、`Article N`。切分后保留层级（父条款 id），每条带 `page_no / bbox / char_start / char_end`。这是"条款级检索/审查"区别于"全文塞给 LLM"的地基。

### 2.6 MinIO（对象存储）

- S3 协议，生产可换阿里云 OSS/AWS S3 不改代码（boto3 兼容层）。合同原文（PDF/DOCX/图片）存 MinIO，PG 只存元数据与解析结果——**事实源分离：结构化在 PG，二进制在对象存储**。
- 上传即生成 `object_key = contracts/{contract_id}/{sha256}.pdf`（内容寻址，天然防重）。

## 3. 详细设计（伪代码级）

### 3.1 数据模型

```sql
CREATE TABLE contracts (
    id            UUID PRIMARY KEY,
    filename      TEXT NOT NULL,
    object_key    TEXT NOT NULL,          -- MinIO 路径
    sha256        CHAR(64) NOT NULL UNIQUE,
    mime_type     TEXT NOT NULL,
    size_bytes    BIGINT NOT NULL,
    source_format TEXT NOT NULL CHECK (source_format IN
        ('pdf_text','pdf_scan','pdf_encrypted','docx','doc','wps','image')),
    parse_status  TEXT NOT NULL DEFAULT 'uploaded',   -- uploaded/parsing/parsed/failed
    parse_confidence REAL,                           -- 0~1，OCR/降级路径标低
    uploaded_by   UUID REFERENCES users(id),
    created_at    TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE clauses (
    id           UUID PRIMARY KEY,
    contract_id  UUID REFERENCES contracts(id) ON DELETE CASCADE,
    parent_id    UUID REFERENCES clauses(id),        -- 条款层级
    seq_no       INT NOT NULL,
    heading      TEXT,                               -- "第七条 违约责任"
    text         TEXT NOT NULL,
    page_no      INT,                                -- DOCX 降级路径可为 NULL
    bbox         JSONB,                              -- [x0,y0,x1,y1] 归一化 0~1
    char_start   INT, char_end INT,                  -- 全文字符偏移，给 LLM 定位用
    parse_confidence REAL,
    CONSTRAINT uq_contract_seq UNIQUE (contract_id, seq_no)
);
```

### 3.2 统一数据结构（三解析器输出同一形态）

```python
@dataclass(frozen=True)
class LineItem:
    page: int            # 0 表示"无页概念"（DOCX 降级）
    text: str
    bbox: BBox | None    # 归一化 0~1 相对坐标：x/page_w, y/page_h
    char_start: int; char_end: int

@dataclass
class ParseResult:
    lines: list[LineItem]
    tables: list[Table]          # {rows: list[list[str]], page: int, bbox}
    source_format: str
    confidence: float
    warnings: list[str]          # e.g. "cid_font_page_3", "table_unparsed_p5"
```

### 3.3 detector（格式探测）

```python
async def detect(file: FileMeta) -> FormatDecision:
    kind = sniff_magic(file.head_bytes)          # %PDF / PK(zip=docx) / D0CF11E0(doc) / image
    match kind:
        case "pdf":
            if pypdf_is_encrypted(file):  return Dec("pdf_encrypted", block=True)
            chars_per_page = probe_text_density(file)     # pdfplumber 抽前 3 页
            if chars_per_page < SCAN_THRESHOLD(50):       # 无文本层/极少
                if garbled_ratio(chars) > 0.3:            # CID 字体乱码
                    return Dec("pdf_scan", reason="garbled")
                return Dec("pdf_scan")
            return Dec("pdf_text")
        case "zip": return Dec("docx")
        case "ole": return Dec("doc")                     # .doc/.wps → 转换通道
        case "image": return Dec("image")
```

### 3.4 三解析器核心伪代码

```python
class Parser(Protocol):
    async def parse(self, src: BinaryIO) -> ParseResult: ...

class PdfTextParser:
    def parse(self, src):
        lines, offset = [], 0
        for page in pdfplumber.open(src).pages:
            words = page.extract_words(use_text_flow=False)   # 词级坐标
            rows = cluster_rows_by_y(words, tol=2)            # y 轴聚类重建行序（双栏友好）
            for row in rows:
                text = join_words(row)
                lines.append(LineItem(page.number, text,
                    bbox=normalize(row.bbox, page.width, page.height),
                    char_start=offset, char_end=offset+len(text)))
                offset += len(text)
        tables = page.extract_tables()    # 线框表格单独抽出
        return ParseResult(lines, tables, "pdf_text", confidence=0.98)

class OcrParser:   # PaddleOCR 路径
    def parse(self, src):
        imgs = pdf_to_images(src, dpi=200)        # 扫描 PDF 先栅格化；图片直接用
        all_lines = []
        for page_img in imgs:
            result = paddle_ocr.predict(page_img)  # det+rec
            for box, text, score in result:
                all_lines.append(LineItem(page, text,
                    bbox=normalize_paddle_box(box, img_w, img_h),
                    char_start=..., char_end=...))
        # OCR 错字不在此修复——M2 evidence 用"模糊匹配"容错（见 M2 §3.5）
        return ParseResult(all_lines, tables=[],
                           "pdf_scan", confidence=avg(score) * 0.9)

class DocxParser:
    def parse(self, src):
        pdf_bytes = libreoffice_convert(src, to="pdf")   # 主路径：转 PDF 取坐标
        para_map = extract_docx_paragraphs(src)          # python-docx 段落+表格顺序化
        pdf_lines = PdfTextParser().parse(pdf_bytes).lines
        aligned = align_paragraphs_to_lines(para_map, pdf_lines,
                    matcher=difflib_ratio(threshold=0.75))  # 文本对齐
        return ParseResult(aligned, tables, "docx", confidence=0.9)
        # 转换失败 → 降级：段落级定位（page=NULL, bbox=NULL），confidence=0.6
```

### 3.5 条款切分

```python
HEADING_PATTERNS = [
    r"^第[一二三四五六七八九十百千\d]+条", r"^[一二三四五六七八九十]+、",
    r"^（[一二三四五六七八九十]+）", r"^\d+\.\d+", r"^Article\s+\d+",
]
def split_clauses(lines) -> list[ClauseNode]:
    nodes, cur = [], None
    for line in lines:
        if m := match_any(line.text, HEADING_PATTERNS):
            cur = ClauseNode(heading=line.text, level=infer_level(m), lines=[line])
            nodes.append(cur)
        elif cur: cur.lines.append(line)
        else: preamble.append(line)          # 标题/甲乙方头不算条款，单独存
    return build_tree(nodes)                  # 按 level 挂 parent_id
```

### 3.6 API 契约

```
POST /api/v1/contracts
  multipart: file；白名单：pdf/docx/doc/wps/jpg/png，≤ 50MB
  流程：校验 → 算 sha256（重复上传返回 200+已存在 id，幂等）→ 存 MinIO → INSERT contracts(status=uploaded)
        → arq 入队 parse_task(contract_id)（M1 即异步：解析可能 1~3 分钟）
  resp 202: {"contract_id", "task_id"}

GET /api/v1/contracts/{id}          → 元数据 + parse_status + source_format + confidence
GET /api/v1/contracts/{id}/clauses  → 条款树 JSON（含 bbox/page/char 偏移）
GET /api/v1/contracts/{id}/pages/{n} → 页图（前端高亮底图；OCR 路径返回栅格化图）
```

### 3.7 arq 任务（M1 起建立任务模式，M6 平滑换 Kafka）

```python
async def parse_task(ctx, contract_id: str):
    # 任务状态机 pending→running→success/failed；arq 重试 3 次、指数退避
    contract = await repo.get(contract_id)
    await repo.update_status(contract_id, "parsing")
    decision = detect(await minio.download(contract.object_key))
    if decision.block:                       # 加密 PDF：明确阻断，不静默降级
        await repo.update_status(contract_id, "failed", reason="encrypted")
        return
    result = PARSERS[decision.format].parse(src)
    async with db.transaction():             # 解析结果与状态在一个事务落库
        await clause_repo.bulk_insert(contract_id, split_clauses(result.lines))
        await repo.mark_parsed(contract_id, result.source_format, result.confidence)
```

## 4. 生产复杂性应对（M1 核心章）

### 4.1 降级矩阵（每种输入的明确出路——**绝不允许静默降级**）

| 语料形态 | 解析 | 坐标 | M4 高亮 | M2 溯源 | 处置 |
|---|---|---|---|---|---|
| 文本型 PDF | 完整 | 词级 | 精确 | 精确 | 正常 |
| 扫描型/图片（OCR） | 完整但有错字 | bbox（精度略低） | 可用 | 模糊匹配容错 | 正常但慢（CPU 推理） |
| 加密 PDF | **失败** | ❌ | 不可用 | 不可用 | **阻断，提示解密后重传** |
| DOCX | 完整 | 段落级（转 PDF 后行级） | 转换成功→精确；失败→段落级 | 相应降级 | `parse_confidence` 标注 |
| 旧 .doc/.wps | 转 PDF 后同上 | 转 PDF 后 | 同上 | 同上 | 转换通道 |
| CID 字体乱码 PDF | 文本层不可用 | ❌ | — | — | 自动转 OCR 路径 |
| 巨大 PDF（>300 页） | 部分 | — | — | — | 分页流式解析 + 任务超时上限（10min），超时标 failed 并提示拆分 |

### 4.2 失败模式与处置

| 失败 | 处置 |
|---|---|
| LibreOffice 转换挂起 | 子进程 timeout=120s，kill 后走段落级降级路径，不阻塞任务 |
| PaddleOCR 内存超限（大图） | 限制单页像素上限（先缩放）；ocr worker 独立部署，崩了不拖垮 api |
| 表格无线框（三线表/纯文字排版表格） | `extract_tables` 失败 → 按行启发式提取 + warning 标记 `table_unparsed`，人工样本集覆盖 |
| 解析中途崩溃重试 | 任务幂等：重试前清掉该 contract 旧 clauses 再插（或 upsert by (contract_id, seq_no)） |
| 用户上传非合同文件 | M1 不做内容判断（M3 审查自然暴露）；只做格式与大小防线 |

## 6. 验收文档（DoD）

- [ ] 10 份合同正文完整率达标且**按形态分开统计**：文本型 ≥95%、扫描型 ≥90%、DOCX ≥95%（证据：人工核对记录表）
- [ ] 条款切分准确率 ≥ 90%（人工标注对比，分形态统计）
- [ ] 任一条款可回标原文坐标：文本型画框命中率 100%，OCR 型 ≥95%（视觉容差内）（证据：前端临时页或测试截图）
- [ ] 表格内容不丢（抽查 5 份含金额表合同）
- [ ] 加密 PDF 被正确识别并阻断，返回友好 problem+json 而非 500
- [ ] 解析器单测 ≥ 85%，全离线可跑（证据：pytest 输出）
- [ ] 上传接口 202 + task_id；解析为异步任务，API 不阻塞

**演示脚本**：上传 20 页 PDF → 展示条款树 → 点某条款 → 原文页画框 → **再传扫描件，OCR 路径同样画框**。

**Gate 回写区**：G1 ☐ / G2 ☐ / G3 ☐（完整率/切分准确率数字回写路线文档）/ G4 ☐。

## 7. 风险与回滚

| 风险 | 缓解 / 回滚 |
|---|---|
| 版式千奇百怪覆盖不完 | 先覆盖「常见合同模板 + 常见扫描质量」，其余整段降级 + 低置信标记 |
| PaddleOCR 依赖冲突 | 独立 dependency group / 独立容器；fallback 链路：OCR 挂 → 任务标 failed 明确报错（不是静默丢坐标） |
| LibreOffice 容器重 | 按需启动（转换任务时才拉起）；或独立转换服务 |
| OCR 精度不达标 | 升级 PP-OCRv5 → 换更高分辨率栅格化（300dpi）→ 数据不出域前提下仍本地推理 |
